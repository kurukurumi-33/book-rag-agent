## 要放哪几张

**1. 一排书脊**（最重要的一张）

就是二手书群里那种：一个书架上十几本，或者一摞书侧面露出的书脊。
这是这个功能的**主场，也是最难的一档** —— 字小、常竖排、有反光、
被相邻的书挤掉一半。

**2. 一本书的封面/扉页**（对照组）

单独一本、字清楚。用来确认「链路本身是通的」——
如果连这张都认不出，那是代码或 key 的问题，不是识别难度的问题。

**3. 一张明显不是书的图**（负例）

风景、自拍、外卖单都行。期望 `recognized_books: []`。
如果模型对一个自拍硬编出一个书名，说明 prompt 里的「不要猜」没拦住 ——
这个负例比正例更能说明问题。

## 看输出时，重点不是「有没有命中」

模型在书脊上**会漏，也会编**。这两件事不是一个量级：

- **漏**（有书没列出来）→ 你少看几本，但你知道自己拍了几本，能发现。
- **编**（列了一个图里没有的书名）→ 这个名字进检索，库里有 2869 个书种，
  它多半能捞回几条**看着挺像的结果**。你没法分辨。

所以验收动作是：**对着原图逐本核左边那列书名，有没有图里根本没有的。**
只检查「有没有命中」是查不出这个失效模式的。

## 顺带一提：认出 25 本只检索了 20 本是正常的

识别是一次模型调用（认 1 本和认 30 本一样贵），检索是每本一次完整链路
（真算力），所以两个上限分开设。脚本会把这个差额打出来：

```
📖 识别出 25 本：...
   ⓘ 只检索了前 20 本（接口上限），剩下 5 本没搜
```

## 体积

接口上限是 base64 后 8 MB，原图控制在 6 MB 以内最稳。手机原图一般 2~4 MB，
微信存下来的通常还会更小，直接放进来就行，不用压缩。
