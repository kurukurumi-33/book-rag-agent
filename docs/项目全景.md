## 0. 一句话

**智觅**（一句话找到你要的二手书）：把二手书交易里混乱的自然语言帖子变成可语义检索的
结构化数据，再用一个会自己决定查不查库的对话 agent 帮学生找书。

核心是两条链路：RAG（抽取 → 向量化 → 检索）和 Agent（tool calling），CRUD 只是外壳。

```
用户：「有笔记的线代，不要超过 30 块」
  → 模型自己拆参数，自己决定调哪个工具、调几次
  🔧 search_books({"query":"线性代数","has_notes":true,"price_max":30}) → 5 条
  🔧 get_post_detail({"post_id":139})                                    → 1 条
  → 「139 号《线性代数》有笔记且划过重点，8 元，还在售」
```

## 1. 两条铁律（整个架构的约束来源）

| | 内容 | 推论 |
|---|---|---|
| 铁律一 | AI 服务不直连业务数据库 | 要数据就调主服务 REST；AI 服务完全无状态，可随便重启、可水平扩副本 |
| 铁律二 | 业务数据的主人是 Spring Boot | 校验、事务、状态流转都在主服务；AI 服务只负责「理解」 |

这两条否决掉的东西（面试常问「为什么不用 XXX」）：

- 不用 LangChain 自带的三种会话历史（`InMemory` / `SQLite` / `RedisChatMessageHistory`），它们都会让 Python 侧持有持久化状态，所以历史改存 MySQL，由 Spring Boot 拥有
- 不让 Python 直接连 MySQL 做检索，那就没有「双服务」这个架构亮点了

代价：每次取数据多一跳 HTTP（`get_post_detail` 的 N+1 就是这么来的）。
换来的是：AI 服务可以换模型、换向量库而完全不动业务侧。

> **⚠️ M4.5 之后加了一句重要区分**（不然会被问住：「你 AI 服务不是用 Redis 了吗？」）
> 铁律约束的是**业务数据**，不是**运维态**。会话历史仍然在 MySQL、仍然由 Spring Boot 拥有；
> Redis 里只有限流计数和一份**丢了也不影响正确性**的历史缓存 —— 丢了只是慢一点，回主服务读一遍就对。
> 反过来，限流计数**必须**放进程外：放进程内，扩两个副本就是各限各的，等于没限。

## 2. 模块地图：每个部分的作用

### 启动时的三条流水线

```
① 造数据   gen_mock_posts.py ──POST /api/posts──▶ MySQL (extractStatus=PENDING)
② 抽取     POST /api/posts/extract-pending ──▶ Python /extract/batch ──▶ 按下标写回 DONE
③ 建索引   POST /index/build ──GET /api/posts?extractStatus=DONE──▶ compose_text → BGE → Chroma
```

③ 最容易被漏：`data/`（Chroma）在 `.gitignore` 里，新克隆的仓库索引是空的。
不跑 `/index/build` 的话 `search_books` 永远返回 0 条，表现成「agent 说找不到任何书」，
很容易误判成代码坏了。

### 运行时的数据流

```
浏览器
  │ POST /api/chat
  ▼
book-service (Spring Boot :8080)
  │ ChatController → AiServiceClient        ← 只做转发，不解析 body
  ▼
ai-service (FastAPI :8000)
  │ chat_once() → LLM
  │    ├─ 工具 search_books      → BGE 编码查询 → Chroma → 过滤 → top_k
  │    └─ 工具 get_post_detail   → HTTP 回调 ─┐
  │ 中间的历史读写 ────────────────────────────┤
  ▼                                          ▼
                                       book-service REST ──▶ MySQL
```

## 3. 三条链路的知识点

### M1 —— RAG 抽取

| 知识点 | 一句话结论 |
|---|---|
| 幻觉式补全 | 帖子里没提出版社，模型会编一个。规则写在 prompt 开头不管用（第 5 条） |
| 没定义的边界 = 线上随机故障 | 同一句原文被抽成两种书名（「毛概」3 条 vs 全称 5 条），因为 prompt 的归一化词表里没有它（第 6 条） |
| 归一化词表不该写在 prompt 里 | prompt 里改一次要重抽全库，配置里改一次只影响新帖 |
| 批量抽取的并发 | 串行 for → `asyncio.gather` + `return_exceptions=True`，单条失败不中断整批，8.1s → 1.5s（第 7 条） |
| DeepSeek 不支持 `json_schema` | 只能用 `function_calling` 模式（第 3 条） |
| 按下标对齐写回 | 批量结果和请求列表靠下标对应，不能靠顺序或内容匹配 |

### M2 —— 向量检索

| 知识点 | 一句话结论 |
|---|---|
| `compose_text()` 不含价格和成色 | 向量管「是哪本书」，条件过滤交给结构化字段。这是分工，不是妥协 |
| 相似度阈值是正确性的一部分 | 向量检索永远返回 top_k 条。搜「量子力学」，关掉阈值会返回 5 本《高等数学》（0.4819） |
| 阈值 0.61 的来历 | 21 条用例卡出来的：最高越界查询 0.6034 / 最低正例 0.6187。缝只有 **0.015**，很薄（1 万条语料上重扫过 0.58~0.65） |
| 条件词稀释查询向量 | 「带笔记的便宜线代」整句丢进向量 → 返回空。根因在查询侧，调阈值治标（第 13 条） |
| 三个不报错的坑 | ① BGE 不加指令前缀 ② `distance` 和 `score` 的换算 ③ 阈值漂移（第 10 条） |
| 懒加载模型 = 第一个请求背锅 | BGE 首次调用才载入，演示前必须预热（第 11 条） |
| 为什么不用 `LIKE` 关键词检索 | 实测 `book_name LIKE '%高数%'` 命中 0 条，而库里有 12 条《高等数学》（第 15 条）。**但这不等于「关键词没用」** —— 后面加的 BM25 恰恰补的是这块，见 M2.5 |

A/B 实测的拼法结论（都用真实数据跑的）：

- 重复书名不加强权重反而削弱：0.6258 → 0.6054 → 0.5953
- 字段顺序影响分数（±0.04），不影响 top-1
- `None` 拿「未知」占位会毒化检索（全体掉 0.03~0.11，因为「未知」区分度为零）

### M2.5 —— 混合检索 + 精排

| 知识点 | 一句话结论 |
|---|---|
| 中文上 BM25 必须自己分词 | BM25 默认按空格切词，中文整句会被当成一个词 = 完全失效。所以先过 jieba（`app/services/lexical.py`） |
| 两路怎么合 | **RRF（倒数排名融合）**：只用名次不用分数，省掉了「余弦 0.68 和 BM25 7.4 怎么加权」这个没法回答的问题 |
| 混合检索的真实收益 | top-3 只变 **1/16**，top-10 变 5/16。收益在**清尾部**（挤掉同书重复帖），不在提命中率 —— 别吹成「准确率大涨」 |
| bi-encoder 粗排 vs cross-encoder 精排 | 粗排快、可离线建索引、只算整体语义；精排逐对算、能分清「考研数学复习书」这种用词不同但相关的。所以是两段式，不是二选一 |
| **rerank 改善排序，不改善过滤** | 正例 top-1 15/16 → 16/16，但越界查询 1/8 → **1/8 一动没动**。指望它拦越界会失望 |
| 精排阈值不启用 | 正例侧只有 0.03 宽（正例 [0.6987,0.7311] vs 越界 [0.5324,0.7151]），切一刀 = 拿 16 条样本过拟合 → `rerank_min_score = None` |
| 精排只能重排召回池里的东西 | 粗排没召回的，精排**根本没被调用**（`if not fused: return []` 提前返回）。所以「条件词稀释」那类问题它救不了 —— 那是查询理解层的事，M3 的 agent 拆解才是解 |

### M2.6 —— 多模态以图搜书

| 知识点 | 一句话结论 |
|---|---|
| 链路选择 | 图 → VLM 抽书名 → **复用 `search()`**。BM25、RRF、精排、阈值全部自动生效，一行没重写 |
| 为什么不是「图 → CLIP 向量」 | 语料是**纯文本**的、没有封面图，**图像索引建不出来** —— 不是建得慢，是没东西可建。要做「找同款封面」才该换 CLIP |
| **抽的是一批书名，不是一个** | 真实输入是**一排书脊**（二手书群里十几本书拍一张）。只回一个书名 = 随便挑一本，且调用方看不出其余被丢 —— 静默降级。旧版 `splitlines()[0]` 更狠：模型列了五行，被切掉四行 |
| **两个上限分开设** | 识别 30（一次模型调用，认 1 本和认 30 本一样贵）/ 检索 20（每本一次完整链路，真算力）。差额靠 `len(results) < len(recognized_books)` 露给调用方 |
| **上限被真实照片顶过一轮**（20/10 → 30/20） | 真图里有 17 本，旧上限截掉 40%。**上限设得比真实输入还紧 = 把闸门装在水管中间**，而且丢掉的那几本是**静默**丢的 |
| **书脊是最难的一档** | 字小、竖排、反光、被邻书挤掉一半。模型会漏**也会编**。编出来的书名照样能检索出看着挺像的结果 —— 漏一本只是少看几本，编一本用户没法分辨。prompt 里明写「不要猜」只是降概率。⚠️ **合成图（5/5 全中、零编造）证明的是链路通，不是识别准** |
| **规则不能假设输入有标签** | 真图实测：20 条输出里 6 条不是书名（`吴传生主编`、`北京大学出版社`、`学生用书`、`（2021年版）`）。原有规则要求行首是「作者：」这种**带冒号**的形式，而模型抄的是书脊上的**裸正文** —— 一条都没拦住。**规则本身没错，错在它假设了输入长什么样** |
| **编一个泛词比编一个书名危险** | `学生用书` 检索出《走遍法国2 学生用书》《新视线俄语1 学生用书》—— **结果页看着完全合理**。编一个不存在的书名，用户一眼看出不对；编一个泛词，用户没有线索 |
| **单测全绿 ≠ 输入分布对了** | 改之前 40 条视觉单测全绿，因为它们测的全是「我想象的输入」。**测试只能证明「在我的假设下是对的」；假设错了，测试越全越有安全感** |
| 残留问题，未修 | 版次被粘进书名（`经济数学微积分-第4版`）、两本书名被合成一个（`新时代大学英语`）、被遮挡的书认不出来。**且两次跑结果不一样（20 本 vs 16 本）—— 上面这些数字都是单次观测，不是稳定指标**。诚实结论：这个功能的上限是「帮你少翻几页」，不是「替你确认书在不在库」 |
| **限流在参数校验之前** | 非法图片（400）**也占额度**。有意为之：垃圾请求同样该被挡，否则「传错东西」就是一条免费通道。实测第 11 次请求回 429 + `Retry-After: 21` |
| 识别不出来不是错误 | 图里没书就返回 `recognized_books: []` + 空 results，不是 4xx。用户的图确实可能是张风景 |
| 校验顺序 | **先校验请求参数，再看服务配置**。第一版写反了，没配 key 时畸形图片返回 503 而不是 400，实测才发现 |
| 不可信输入止于检索边界 | VLM 的输出只当一个 query 字符串，**永不进 prompt**。这是设计出来的属性，不是碰巧。返回一串书名没削弱它 —— 判断标准是「有没有回到 prompt 里」，不是「返回了几个字符串」 |
| **它曾漏了整整一个里程碑的限流** | 走 `/search` 的路径、名字也像检索，被顺手归进「检索不烧 key 不限流」那类 —— 但它第一步就是视觉调用。限额 10/分钟，比 `/chat` 还紧（**按成本归类，不按 URL 前缀归类**） |

### M4.5 —— 限流与缓存（Redis）

| 知识点 | 一句话结论 |
|---|---|
| 为什么限流计数必须放进程外 | 放进程内，扩两个副本就是各限各的 = 等于没限。这跟「AI 服务无状态」不冲突：限流计数是**运维态**，不是业务数据 |
| 固定窗口的漏洞 | 0:59 打满 20 次 → 1:00 再打满 20 次 = 两秒 40 次。滑动窗口（ZSET + `ZREMRANGEBYSCORE`）没这个洞 |
| ZSET member 必须唯一 | 直接用时间戳当 member，同毫秒的并发请求会塌成一条记录，限流被静默架空 → 用 `时间戳-uuid` |
| 四条命令必须进一段 Lua | 分开写会 race：两个请求都读到 count=19、都放行 → 21 次。Lua 保证清理+计数+判断+写入原子 |
| 挂了是放行还是拦截 | **fail-open**（放行 + warning + `/health` 可见）。限流是保护不是正确性，为保护把服务变成单点不划算。**降级路径本身也写了测试** |
| 为什么不用 `X-Forwarded-For` | 客户端随便写，一行命令绕过。用 TCP 对端地址；真上生产在 uvicorn 开 `--proxy-headers` + 白名单 |
| 缓存为什么用失效不用写穿 | 写穿要求缓存**复刻主服务的截断逻辑**（limit + 排序）= 第二份业务逻辑。失效只保证缓存里只可能是服务真的返回过的东西 |
| 缓存 key 必须带 `limit` | 否则先读 `limit=2` 再读 `limit=20` 会「agent 突然失忆」，而且**只有调用顺序变了才复现** |
| 测试替身可能替掉被测逻辑 | 内存假 Redis 用 Python 重写了滑动窗口，于是 Lua 根本没被测到 —— 「测试和一个错误实现达成了一致」。所以另写了真连 Redis 的集成测试 |

### M3 —— Agent

| 知识点 | 一句话结论 |
|---|---|
| tool calling 协议 | 模型只下工单不动手：`content=''` + `finish_reason='tool_calls'` + `tool_calls=[{name,args,id}]` |
| 工单↔回执双向配对 | 一条 `tool_calls` 必须跟一条 `ToolMessage`。想「跳过坏数据」是反的（第 17 条） |
| 循环终止判据 | 只看 `tool_calls` 空不空，不能看 `content`，因为模型下工单时也可能顺口说一句话 |
| 历史规则 | 只留 `HumanMessage` 和最后那条 `AIMessage`；中间的工具往返必须成对，只留一半下一轮直接报错 |
| `recursion_limit` 默认 10007 | 等于没有护栏。实测 N 轮 = 2N+1 节点 → `MAX_ROUNDS=5` 配 `12` |
| 框架版反而多 5 行 | 手写 38 行 vs 框架 43 行（用 AST 挖掉 docstring 数的）。框架省的其实是协议坑，行数上并不省 |
| N+1 修复 | prompt 加「没指明是哪本就先问清楚」→ 从 6 次工具调用降到 1 次 |

三态字段（这个坑犯过两次，第二次才认出是同一类）

| 字段 | 怎么被压成两态的 | 正解 |
|---|---|---|
| `has_notes` | `bool(p.get("hasNotes"))` 把 None（卖家没提）压成 `False` | 回源头取真值，出口是「未提及」 |
| `price` | `null` 同时表示「没标价」和「面议」 | 出口是「未标价」，不替卖家承诺可以还价 |

> 一句话记住：源头分不清的事，出口不能替它下结论。

## 4. 工程知识点（横切）

| 领域 | 知识点 | 关键点 |
|---|---|---|
| 服务间通信 | Spring Boot 4 默认 JDK HttpClient 会试 `Upgrade: h2c` | uvicorn 不支持 → body 丢失，而 FastAPI 报「字段缺失」完全不提 HTTP/2。修法：显式 `SimpleClientHttpRequestFactory`（第 9 条） |
| | `localhost` vs `127.0.0.1` | Windows 上 `localhost` 同时解析 IPv4/IPv6，uvicorn 只绑 IPv4 → 服务起着却连不上 |
| 序列化 | Jackson 2 和 3 同时在 classpath 上 | Boot 4 换成 Jackson 3（`tools.jackson.databind`），Jackson 2 是 springdoc 带进来的。编译过、启动正常、第一个真实请求才 500（第 19 条） |
| | 定位技巧 | 看异常链最底下那条的包名，不是最上面那条 |
| | `JsonNode` 不吃 `non_null` | `non_null` 会省掉实体的 null 字段，但不作用于 `JsonNode`（NullNode 是节点不是空值） |
| 校验 | `%2F` 被 Tomcat 容器层直接 400 | 防目录穿越。`quote()` 转义救不了 → 结论是约束字符集（`^[A-Za-z0-9_-]{1,64}$`）而不是想办法转义 |
| | Pydantic 的 `pattern` 不锚定 | 写 `[A-Za-z0-9_-]{1,64}` 时 `"a/b"` 含一个 `a` 就通过 → 必须自己写 `^...$` |
| | `@Pattern` 对 null 放行、对空串失败 | 正好是 `session_id` 需要的（null = 新会话合法，空串不合法） |
| 错误响应 | `include-message: always` 只在 `BasicErrorController` 渲染时生效 | 不会给 `MethodArgumentNotValidException` 加 `message`；而且 `non_null` 会把 Map 的 value 也过滤掉 → 键直接消失 |
| | DTO 校验消息要自带字段名且用对外名字 | `FieldError.getField()` 给的是 Java 属性名 `sessionId`，调用方拿着去查自己的请求会找不到那个键 |
| 并发 | `@Transactional` 让消息对原子化 | 所以同会话并发不会写出 `human,human,ai,ai`，而是干净的 `h,a,h,a` |
| | 压测要选风险所在的那一层 | 风险在 embedding 单例 + Chroma，不在 LLM（远程 HTTP 无共享状态）→ 压 `/search`，且零成本 |
| | 「没崩」≠「算对了」 | 要比逐字节一致，不能只看 200（第 22 条） |
| 工程实践 | 验收顺序：编译 → 启动 → 打个真实请求 | 只跑到第二道就交付，Jackson 那个 bug 会留到演示当场 |
| | 数行数必须用 AST 挖掉 docstring | 按「非空非注释」数会得出「框架省了 40 行」的假结论（第 18 条） |
| | `except 未定义名字:` 是惰性求值 | 跑顺时毫无征兆，真抛异常时 `NameError` 把原始异常顶掉 |
| | **装饰器捕获紧跟其后的 `def`** | 辅助函数插进 `@app.post("/search")` 和 `def search()` 之间 → 路由静默改绑，全部 422。服务照常启动、`/docs` 照常打开、单测全绿（没有一条走 HTTP 打它）。**只有「HTTP 层路由绑定测试」能抓到** |
| 测试 | 单测、集成、路由三层各管一段 | 单测快但不起服务，抓不到路由/序列化；集成真连 MySQL/Redis；`test_routes.py` 用零依赖守住「每条路径绑定到哪个函数」 |
| | 降级路径也要有测试 | fail-open 不是「没写错误处理」，是一条**要主动验证**的分支。测 Redis 挂掉时 429 变 200，跟测正常限流一样重要 |
| | 测试替身会替换掉被测逻辑 | 内存假 Redis 用 Python 重写了滑动窗口，Lua 根本没被执行 —— 「测试和一个错误实现达成了一致」。凡是逻辑写在 Redis/Lua/SQL 里的，必须真连一次 |
| | 状态挪到进程外，测试间就会互相污染 | 限流桶在 Redis 里（进程外），上一个用例的计数会让下一个用例第一次请求就 429 → fixture 里先删 `zhimi:rl:*` |

## 5. 面试考点（按被问概率排序）

### 第一梯队 —— 几乎必问

**Q1「讲一下这个项目的架构」**
> 双服务：Java 管业务和数据，Python 管理解和检索。**AI 服务不直连数据库**，
> 要帖子数据就调主服务的 REST 接口。代价是每次多一跳 HTTP，
> 换来 AI 服务完全无状态、可以随便重启和扩副本。
> 最直观的体现是 agent 的 `get_post_detail` 这个「本地工具」其实是一次跨进程 HTTP 调用。

**Q2「Agent 是怎么实现的」**
> 手写了一个 tool calling 循环：模型返回 `tool_calls` 就执行工具、把结果包成
> `ToolMessage` 喂回去，直到模型返回纯文本。
> 我控制的是给了它哪几个工具和最多循环几轮（`recursion_limit=12`），
> 具体调哪个、调几次是模型自己决定的。
> 后来还用 LangChain 重写了一版做对照，**实测框架版反而多 5 行**。

**Q3「检索阈值怎么定的」**
> 21 条用例卡出来的，最高越界查询 0.6034、最低正例 0.6187，**0.61** 落中间。
> **但我主动说：这条缝只有 0.015，很薄。**
> 一开始我用 4 条反例定成 0.58，看着有 0.144 的余量，
> 补完用例后一条难负例直接越过它。那个 0.144 不是模型的安全边际，是测试集太弱的产物。
> 后来语料从 220 扩到 1 万，分数整体漂移，我又重扫了一遍 0.58~0.65 才定回 0.61 ——
> **换语料必须重标阈值，老阈值不能直接搬。**

**Q3b「那 8 条拦不住的越界查询呢」**（问阈值几乎必被追问）
> 全落在正例区间内，最高 0.7301。我拿 top-1、相对均值的 gap、标准差逐个试过，
> **任何阈值形态都分不开** —— 越界「教育学」的 top1−均值 = 0.0070，比正例「同济版高数」的 0.0018 还自信。
> 所以我没继续调阈值，而是上了 rerank。**结果 rerank 也没救回来（1/8 → 1/8）。**
> 拆开看才明白：拦不住的分两类 ——
> A 类（核工程 0.5324 / 环境工程 0.5473）模型其实看穿了，但正例下界 0.6987，中间 0.03 宽的空隙切一刀就是拿 16 条样本过拟合，
> 而且**代价不对称**：漏一条越界只是看到一本沾边的书，误杀一条正例是搜不到本来有的书。
> B 类（纺织→《这个词是怎么来的》、法学概论→《法律的概念》）**根本不是越界，是主题相邻的真实书**，精排给 0.67~0.72 是对的。
> 该修的是产品定义，不是检索链路。

**Q3c「rerank 带来了什么」**
> **改善了排序，没改善过滤。** 正例 top-1 从 15/16 到 16/16，反例和越界查询一动没动。
> 所以我**没启用精排阈值**（`rerank_min_score = None`）——
> 正例侧只有 0.03 宽，切一刀就是过拟合。面试别说成「准确率提升 X%」，就说这个。

**Q4「为什么需要相似度阈值」**
> 向量检索永远会返回 top_k 条，哪怕库里没有这本书。
> 我在演示里现场对比：搜「量子力学」，默认阈值返回 0 条；
> 把 `min_score` 关掉返回 5 本《高等数学》全是 0.4819。
> **阈值不是性能优化，是正确性的一部分。**

### 第二梯队 —— 大概率会问

| 问题 | 一句话答案 |
|---|---|
| 「为什么不用关键词索引？」 | 实测 `LIKE '%高数%'` 命中 0 条而库里有 12 条《高等数学》。选型是被约束逼出来的，不是被先进性驱动的（第 15 条最完整） |
| 「AI 服务用 Redis 了，那不就有状态了吗？」 | 关键区分：**业务数据**和**运维态**。会话历史仍然是 MySQL 的、由 Spring Boot 拥有，Python 从来不碰。Redis 里放的是限流计数和一份**随时可以丢的**会话历史缓存 —— 丢了只是慢一点，重新回主服务读一遍就对。而且限流计数**必须**放进程外：放进程内，扩两个副本就是各限各的，等于没限 |
| 「限流为什么用滑动窗口？为什么放行？」 | 固定窗口有「0:59 打满、1:00 再打满 = 两秒两倍」的漏洞；滑动窗口用 ZSET，清理+计数+判断+写入必须**放进一段 Lua** 才原子，拆成四条命令并发下会双双读到 19 然后都放行。Redis 挂了选 **fail-open**（放行 + 告警日志 + `/health` 可见）—— 限流是保护，不是正确性的一部分，为保护把自己变成单点不划算 |
| 「限流按什么身份？用 `X-Forwarded-For` 吗？」 | **不用。** 那个头客户端随便写，一行命令就绕过去了。用 TCP 对端地址。真上生产该在 uvicorn 开 `--proxy-headers` + `--forwarded-allow-ips` 白名单，让反代去填 |
| 「高并发怎么办？」 | 瓶颈是 LLM（1~5 次调用/请求、每次 1~2 秒、账号级并发限制），不是数据库也不是 embedding（BGE 实测单次 10ms）。抽取那条路有 `max-concurrency: 8` 防 429；`/chat` 和 `/extract` 现在都有 Redis 滑动窗口限流（20 / 60 次每分）。**`/search` 和 `/index/build` 故意不限** —— 它们是本地 BGE、纯 CPU，限了只会伤自己的演示 |
| 「缓存怎么保证一致？」 | **cache-aside + 写时失效**，不是写穿。写穿要求缓存复刻主服务的截断逻辑（limit + 排序），那等于养第二份业务逻辑，迟早跟主服务跑偏。失效只保证一件事：缓存里**只可能**是服务真的返回过的东西。另外 key 必须带 `limit`，否则先读 limit=2 再读 limit=20 会「失忆」，而且只有调用顺序变了才复现 |
| 「为什么检索文本不含价格和成色？」 | 向量管「是哪本书」，条件过滤交给结构化字段。混在一起就是 M2 那条失败验收的根因 |
| 「三态字段是什么？」 | `has_notes` 的「卖家没提」和「明说没有」不是一回事。`bool(None)` 把 99 条「没提」压成「没有笔记」，那是替卖家撒谎（第 6 条 + 如果重做第 2 条） |
| 「pytest 呢？CI 呢？」 | 有：**168 单测 + 40 集成**（单测 16 秒、零外部依赖）。CI 用 GitHub Actions 三个 job。**主动补一句：CI 里不真调 LLM**（conftest 塞假 key），所以 **CI 绿 ≠ 接口能调通** —— key 失效、模型下线它都发现不了。检索质量测试也不进 CI，因为灌语料必须花钱 |
| 「token 成本怎么控的？」 | 挂在 LLM 客户端的 callback 上统计，`GET /usage` 出用量和估算成本（实测单条 1625 入 + 142 出 ≈ 0.0044 元）。**为什么不在调用处数**：`with_structured_output().invoke()` 返回的是解析好的 `BookInfo`，usage 在解析那一步就丢了。callback 是唯一不动调用结构就能拿到的路。另外批量抽取把 system prompt 从「每条发一次」变成「每 20 条发一次」，1 万条帖子 13.4M → 2M token |
| 「怎么保证统计本身没坏？」 | `/usage` 里有一栏 `calls_without_usage` —— 有调用成功返回但没拿到 usage 时它就涨。设它是防「统计失效伪装成成本 0 元」：provider 换个字段名，你会看到一个干净的 0。**统计准不准本身也要可观测** |
| 「服务怎么监控？」 | 每个请求一行耗时日志（middleware，覆盖 404/422 这种没进接口函数的请求）；`/health` 真探主服务（原来那一栏只是配置值，主服务挂了照显正常）。**LLM 故意不探** —— 每次探活烧一次 token，而 key 失效在真调用时自然暴露 |
| 「多模态怎么做的？为什么不用 CLIP？」 | 图 → VLM 抽出书名 → **复用现有 `search()`**，BM25/RRF/精排/阈值全部自动生效，等于白捡。不用 CLIP 的理由是**约束逼的**：语料是纯文本的，一本书一张封面图都没有，图像索引**建不出来**（不是慢，是没东西可建）。硬上 CLIP 只能做成「找同款封面」，那是另一个需求 |
| 「图上识别的文字安全吗？」 | 它是**不可信输入**，所以只当检索词用，**永远不进任何 prompt**。这条边界是设计出来的，不是碰巧 —— 视觉输出和函数返回值在类型上就没法到别的路径去 |
| 「遇到过最难查的 bug？」 | 三个候选：① Jackson 2/3 共存（三道防线全没拦住，第一个真实请求才 500）；② h2c 握手失败（报错说「字段缺失」，真因是 HTTP/2，修法是写个 echo server 抓原始字节）；③ **一个装饰器插错位置让整个 `/search` 静默失效** —— 我把辅助函数插在 `@app.post("/search")` 和 `def search()` 之间，装饰器就把辅助函数当成了路由处理函数，所有请求 422。服务照常启动、`/docs` 照常打开、78 条单测全绿（没有一条走 HTTP 打 `/search`），**是最后加的「路由绑定」测试抓出来的** |

### 第三梯队 —— 加分项（主动说）

- 模型会否认自己收到的输入（第 23 条）。agent 的失败往往表现为一段自信的假话，不会抛出异常
- 我预判的并发 bug 没有出现（第 21 条），因为漏看了自己写的 `@Transactional`。
  主动讲「我猜错了」比讲「我猜对了」更能证明判断过程
- 用一次 30 并发的零成本实验替代 30 次模型调用（第 22 条），体现成本意识
- **上了 rerank 却发现它没解决我本来想解决的问题**（越界查询 1/8 纹丝不动），
  拆开看才分清「排序」和「过滤」是两件事。承认一次升级没达到预期，比硬报一个好看的百分比可信
- **我为一个自己写的 bug 补了一层测试**（装饰器改绑路由）。这比「我没 bug」有价值得多

| 复现 | `eval_search.py --no-rerank --save X` 再 `eval_search.py --save Y --diff X` |

**一句话结论：rerank 改善的是排序，不是过滤。** 指望它「拦住越界查询」会失望 ——
真正被它收服的是「本来答对但排第 2」的那批。面试就答这个，别说成「准确率提升 X%」。

**为什么拦不住的那些还是拦不住**，拆成两类才说得清（详见 `scripts/eval_search.py`
的 `KNOWN_LEAKS` 注释块，那是这个项目最值得读的一段）：

- **A 类：模型看穿了，但没低到能安全切** —— 核工程 0.5324 / 环境工程 0.5473 /
  教育学 0.5794。cross-encoder 确实读出了「工程 ≠ 核工程」，但正例下界是 0.6987，
  中间 0.03 宽的空隙切一刀 = 拿 16 条样本过拟合。而且**代价不对称**：
  漏一条越界 = 用户看到一本沾边的书；误杀一条正例 = 用户搜不到本来有的书。
- **B 类：压根不是「越界」，是主题相邻的真实书** —— 纺织→《这个词是怎么来的》
  （那本就是讲纺织词源的）、法学概论→《法律的概念》、建筑学→《建筑物理》。
  精排给 0.67~0.72 **是正确的**。叫它们 leak 是余弦时代的框架遗留；
  该修的是**产品定义**（用户搜「纺织」时，讲纺织词汇书源的书算不算命中？），不是检索链路。

**⚠️ 换语料必须重做的两件事**（这次踩过）：
1. **重标阈值** —— 分数分布整体漂移（例：「法学概论」的 top-1 从 0.5902 → 0.7004）
2. **重挑负样本** —— 老负样本「量子力学 / 有机化学 / 宏观经济学」在新语料里
   **真的有书了**（12 / 43 / 11 条）。负样本测的是语料不是检索质量，
   语料一变它就失效

### 限流与缓存（M4.5，2026-10-09）

| | 数字 / 设计 |
|---|---|
| 限流算法 | **滑动窗口**（Redis ZSET + Lua 原子）。固定窗口有「0:59 打满 → 1:00 再打满 = 两倍」的漏洞 |
| 限额 | `/chat` 20 次/分/IP；`/extract`+`/extract/batch` 60 次/分**共用一个桶**；`/search`、`/index/build` **不限**（不烧模型） |
| 限流身份 | TCP 对端 IP。**故意不看 `X-Forwarded-For`** —— 那个头客户端随便写，等于一行命令绕过 |
| Redis 挂了 | **fail-open**（放行）+ warning；`/health` 的 `redis.connected` 可见。⚠️ 连上后掉线需重启才恢复 |
| 会话缓存 | **cache-aside + 写时失效**（不用写穿 —— 写穿要求缓存复刻主服务的截断逻辑，那会变成第二份业务逻辑） |
| 缓存 key | 必须带 `limit`，否则先读 `limit=2` 再读 `limit=20` 会「失忆」且只有改顺序才复现 |
| 实测 | 往缓存塞假值 → 再读确实拿到假值（证明读的是缓存）；写一轮后缓存被删；再读拿到真实数据 |
| Redis 版本 / db | 8.10.0 / **db0**（苍穹外卖用 db10，键又都带 `zhimi:` 前缀，不会撞） |

### 多模态以图搜书（M2.6）

| | 数字 / 设计 |
|---|---|
| 链路 | 图 → VLM 抽出**一批**书名 → 逐本复用 `search()`（BM25+RRF+精排+阈值全部自动生效） |
